Scores

Each search's trigger list is scored against the hidden answer key: how many signals it finds at a fixed false-alarm rate, and whether its false-alarm rates are honest. Sensitivity counts only for a search whose false-alarm rates are honest.

Leaderboard

How a search is scored

  1. 1

    The trigger list

    For each dataset, the frozen search writes a CSV file with one row per candidate event: start GPS time, end GPS time, and a false-alarm rate, meaning how often noise alone would produce a candidate this loud.

  2. 2

    Matching

    A trigger matches an injected signal when its interval overlaps the signal in time, within 0.1 s for now. Only signals in analysable time in both detectors, with a computable signal-to-noise ratio, are scored.

  3. 3

    Sensitivity

    Only triggers below the false-alarm-rate threshold count. The fraction of signals found is reported per waveform, against amplitude and against signal-to-noise ratio. For testing the threshold is 1 per week; the final one is not chosen yet (27 November update).

  4. 4

    Held-out classes

    The test set adds five signal classes the agent never sees in training. They are reported separately, and the gap to the training classes measures how well a search finds signals it was never shown.

Checks against cheating

  • Honest false-alarm rates

    The search also runs on noise-only data from the same half of the run. The number of triggers below each rate must agree with what the claimed rates predict; many more means the rates are dishonest.

    • expected = rate × analysed time
    • background by time slides allowed

  • Too-faint signals

    Some injected signals are too faint for any real search to see (signal-to-noise ratio below 2 in the two detectors combined). A search that finds many of them has seen the answer and is flagged. A search that reads the answer key passes the honesty check; only this check catches it.

  • Sealed and offline

    The frozen search runs with no network: O3 strain is public, so subtracting it from the data would reveal every injection. The test set's GPS times are shifted by a secret amount.

The scorer itself is tested with fake trigger lists: one that reports nothing, triggers every second with honest and with dishonest rates, random triggers with dishonest rates, and one that reads the answer key. Each behaves as designed (27 November update).

How it works

  • An AI agent builds a gravitational-wave burst search on documented training data, where it can see where the signals are.
  • Its search is a folder with a script, run.sh <dataset> <out>, that writes a trigger list. The search is then frozen and run, unchanged and offline, on a sealed test set whose signals are hidden.
  • Each trigger list is scored against the hidden answer key:
    • how many signals the search finds at a fixed false-alarm rate;
    • whether its false-alarm rates are honest;
    • how well it finds signal classes it never saw in training;
    • whether it found signals that no real search could see.
  • The design follows the group's high energy physics benchmark, HEP-Ex-Bench, and runs in the same harness.
  • Status: a first scorer runs on the training data. The task is not yet in the benchmark, and no agent has been run on it.

How a search is scored

What the search hands in

For each dataset, a CSV file with one row per candidate event:

Column Content
1 Start GPS time, in seconds
2 End GPS time, in seconds
3 False-alarm rate, in Hz: how often noise alone would produce a candidate this loud

Sky position (right ascension and declination) may be added later as two more columns.

Matching triggers to signals

  • A trigger matches an injected signal when its start-to-end interval overlaps the signal in time, within a tolerance. The tolerance is 0.1 s for now; the final value will be fixed before any results are seen.
  • Only signals that lie in analysable time in both detectors, with a computable signal-to-noise ratio, are scored.
  • A trigger that matches a signal that is not scored is dropped. It counts neither as found nor as a false alarm.
  • Waveforms with known defects in the injected data are left out of every metric.

Sensitivity at a fixed false-alarm rate

  • Only triggers with a false-alarm rate below the threshold count. A signal is found if such a trigger matches it.
  • The fraction found is reported per waveform, against the signal's amplitude (hrss) and against its signal-to-noise ratio in the two detectors combined.
  • Classes are compared at a fixed signal-to-noise ratio, since some were injected louder than others.
  • For testing, the main threshold is 1 per week. The final threshold is not chosen yet.

Honest false-alarm rates

  • The search also runs on noise-only data from the same half of the run.
  • On that data, the number of triggers below each false-alarm rate must agree with what the claimed rates predict (rate × analysed time). Many more than predicted means the claimed rates are dishonest.
  • A search may estimate its background by time slides: shifting one detector's data against the other's, so that any coincidence comes from noise alone.
  • Sensitivity counts only for a search whose false-alarm rates are honest.

Generalization

  • The training signal classes and the held-out classes are reported separately.
  • The gap between the two measures how well the search finds signals it was never shown.

Too-faint signals

  • Some injected signals are too faint for any real search to see (signal-to-noise ratio below 2 in the two detectors combined).
  • A search that finds many of them has seen the answer, for example by subtracting the public LIGO data, and is flagged.
  • A search that reads the answer key passes the honesty check, because it reports nothing on noise. Only this check catches it.

Testing the scorer

The scorer is tested with fake trigger lists:

  • one that reports nothing;
  • triggers every second, with honest rates and with dishonest ones;
  • random triggers with dishonest rates;
  • one that reads the answer key.

Each behaves as designed: the dishonest lists fail the honesty check, and the list that reads the answer key is caught by the too-faint check (27 November update).

Not decided yet

  • the final false-alarm-rate threshold and the final matching tolerance (1 per week and 0.1 s for testing);
  • whether the search also hands in the list of time it analysed;
  • a single combined score, and how runs are ranked;
  • how the test set is cut into sealed pieces;
  • later: the probability that a candidate is a real signal, and latency.

The data

  • Detectors: real LIGO strain from the third observing run (O3), from Hanford and Livingston, at 16,384 Hz.
  • Signals: simulated short bursts (under 10 s) added to the strain.
  • Training data: from the first half of the run (O3a). One set has injected signals and one has noise only. Where every signal is, and what it is, is documented.
  • Test data, sealed: from the second half (O3b), with the same two parts. The signals are hidden.
  • Noise conditions: the injection and noise sets alternate in blocks of about one day from the same run. They see the same noise conditions but share no data.
  • No real events: one detector's data is shifted in time against the other's, so only the injected signals line up between the detectors.
  • Training signals, 39 waveforms:
    • 19 sine-Gaussians: a sine wave under a bell-shaped envelope;
    • 16 white-noise bursts: a short burst of random noise in a frequency band;
    • 4 binary black hole mergers on circular orbits.
  • Test signals: the same 39, plus five classes the agent never sees in training.
  • Against gaming:
    • the test set's GPS times are shifted by a secret amount;
    • the search runs with no network. O3 strain is public, so subtracting it from the data would reveal every injection.
  • Hosting: the data is not on Hugging Face, and where the benchmark will host it is not decided yet.

Reference searches

  • Simple, honest searches will set the bar for the agents.
  • Three deliberately crude toy searches are frozen to test the pipeline: an excess-power search, a small one-dimensional convolutional network on whitened 1 s windows, and an autoencoder trained on noise only.
  • On one day of training data all three ran end to end, with background from time slides. Their false-alarm rates were honest on held-out noise, and they found almost nothing, as expected for toys. They are not baselines; a real baseline is still to come.

Agents

LIGO agents will run through the same harness as HEP-Ex-Bench.

  • Coding tools:
    • Claude Code, Codex and opencode each have a run script, and each runs with the operator's own login;
    • the run record also recognizes Vibe.
  • Models: the model and its reasoning effort are set for each session.
  • Prompts: the LIGO prompts are not written yet.
  • The session:
    • It runs in a sandbox (bubblewrap) with its own empty home folder and caches, and with the evaluator's files hidden.
    • It has a time budget, 2 hours by default in the harness, and is stopped when the budget runs out.
    • An interrupted session can resume with the time it has left.
  • The frozen search runs in a sandbox with the network blocked and the sealed answer key not mounted.
